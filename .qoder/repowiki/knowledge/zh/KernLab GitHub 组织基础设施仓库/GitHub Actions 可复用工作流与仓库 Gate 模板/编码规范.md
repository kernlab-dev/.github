- Reusables 以一位数字阶段前缀命名：e10(evaluate)、v10/v20/v30(vet/build/verify)、m10/m20(merge)、w10/w20(wrap/deploy)、r10(rublish)、o10(operation)，标识在门控流水线中的接入位置。
- 所有 action 引用使用带行内注释的完整 SHA + `# vN` 锚定版本（如 `actions/checkout@... # v4`），禁止浮动 ref。
- reusables 顶部用中文注释段声明触发方式、输入契约、产物依赖及扩展点；gate.yml 入口用分段注释 + `<!-- ... -->` 标注按需启用的扩展节点。
- Gate 入口 job 统一加 `needs.e10-policy.result == 'success'` 前置守卫，并显式 `if: !cancelled()` 条件，避免被取消分支误触后续任务。
- 需要 OIDC 的发布者 job 在 job 层声明 `permissions: { contents: read, id-token: write }`，而非全局提升仓库权限。
